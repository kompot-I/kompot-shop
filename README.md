# BRICKBOX (Vite + Vue 3)

Витрина Lego-минифигурок. Та же логика и дизайн, что были в vanilla-версии,
но теперь разложены по компонентам — так проще расширять и тестировать.

## Запуск

Нужен Node.js **20.19+**, **22.13+** или **24+** (проверить: `node -v`). На более
старом Node `npm run dev` может запуститься, а `npm test` упадёт с ошибкой
`webidl.util.markAsUncloneable is not a function`: это `jsdom` не заводится.

```bash
npm install
npm run dev
```

Откроется на `http://localhost:5173` с hot-reload — любое изменение в `.vue`
файле применяется мгновенно, без перезагрузки страницы.

Другие команды:

```bash
npm run build       # продакшн-сборка в dist/
npm run preview     # локально посмотреть на собранный dist/
npm run test         # прогнать тесты один раз
npm run test:watch  # тесты в watch-режиме, полезно во время разработки
```

В IntelliJ IDEA просто открываете папку проекта и запускаете `npm run dev`
через встроенный терминал — никакого отдельного плагина не нужно.

### Компонент vs composable — в чём разница

Это главное разделение в приложении, и стоит его понимать осознанно:

- **Компонент** (`.vue` файл) — это то, что рисуется на экране. У него есть
  шаблон, и обычно — стили. Пример: `ProductCard.vue` знает, как выглядит
  карточка товара.
- **Composable** (`use*.js` файл) — это переиспользуемый кусок реактивной
  логики без единого тега разметки. `useProductFilters.js` ничего не знает
  о том, как что-то отрисовать — он просто хранит `search`/`condition`/`sort`
  и отдаёт отфильтрованный список. Поэтому его можно протестировать без
  рендеринга UI вообще (см. `composables/__tests__/`) — и в теории использовать
  повторно, например, если появится вторая страница со своим списком товаров.

Грубая аналогия на ваш бэкграунд: composable — это примерно как сервис
в Spring (несёт логику, не знает о представлении), компонент — как
контроллер + view вместе.

### Тесты

Лежат рядом с кодом в папках `__tests__/` — это конвенция JS/TS-экосистемы,
отдельного дерева `src/test/...` как в Java здесь не будет. Стек — **Vitest**
(тот же движок, что у Vite, поэтому конфиг общий) + **@vue/test-utils** для
монтирования компонентов в виртуальном DOM (jsdom).

Два вида тестов:
- Чистая логика без UI: `useProductFilters.spec.js`, `useCart.spec.js`,
  `order.spec.js`, `telegram.spec.js`.
- Проверка данных: `catalog.spec.js` читает `public/products.json` и ловит
  опечатки при ручном заполнении (см. [PRODUCTS.md](PRODUCTS.md)).
- Компоненты целиком: `ProductCard.spec.js`, `CartDrawer.spec.js` — монтируют
  реальный компонент и проверяют то, что увидел бы пользователь: текст на
  экране, disabled-кнопку, клик. Корзину им отдают через `provide`, ровно как
  это делает `App.vue`.

## Формат товара (public/products.json)

Формат прежний, но поле `buyLink` больше не используется: покупка теперь идёт
через корзину. Его можно удалить из товаров или оставить на будущее.

```json
{
  "id": "уникальный-id",
  "name": "Название",
  "category": "Star Wars",
  "description": "Короткое описание",
  "price": 1200,
  "currency": "RUB",
  "quantity": 1,
  "condition": "new | like_new | used",
  "image": "https://... или пусто (будет плейсхолдер)",
  "buyLink": "не используется"
}
```

Подробная инструкция, как заполнять каталог и готовить фото, — в
[PRODUCTS.md](PRODUCTS.md). Фото лежат в `public/images/`, а путь к ним пишется
**без `/` в начале**: `images/sw-001.jpg`.

## Дальше — бэкенд на Kotlin

`src/api/products.js` сейчас делает `fetch("/products.json")`. Когда поднимете
Spring Boot с эндпоинтом `GET /api/products`, отдающим тот же формат
(`{ "products": [...] }`), меняете в этом файле только URL. Ни composables,
ни компоненты трогать не придётся — они работают с массивом объектов, а не
с тем, откуда он взялся.

## Корзина и заказ

Покупатель кладёт товары в корзину (кнопка «В корзину» в карточке, затем
степпер «− / +»), открывает корзину значком в шапке и жмёт
**«Заказать в Telegram»**. Открывается чат с менеджером
(`MANAGER_USERNAME` в `src/config.js`), в поле ввода уже стоит текст:

```
Здравствуйте! Хочу заказать в BRICKBOX:

1. Джедай-рыцарь (sw-001) — 1 × 1 200 ₽ = 1 200 ₽
2. Штурмовик Первого Ордена (sw-002) — 2 × 900 ₽ = 1 800 ₽

Итого: 3 000 ₽ (3 шт.)
```

Покупателю остаётся нажать «Отправить». Это ссылка вида
`https://t.me/<ник>?text=...`, поэтому бэкенд не нужен.

Что важно знать:

- **Количество ограничено остатком** (`quantity` в `products.json`): положить
  больше, чем есть, нельзя.
- **Корзина хранится в `localStorage`** только как `{ id: количество }`. Цены
  и названия каждый раз берутся из актуального каталога, поэтому после смены
  цены в `products.json` корзина покажет новую. Товары, которых в каталоге
  больше нет, из корзины пропадают сами.
- **После «Заказать» корзина не очищается**: мы не знаем, нажал ли покупатель
  «Отправить». Есть кнопка «Очистить корзину».
- Покупатель может поправить текст перед отправкой, и текст ограничен
  4096 символами (длинные корзины урезаются, итог остаётся полным). Если нужна
  защита от подделки, переходите на вариант с ботом и бэкендом (ниже).

### Перейти на заказ через бота и бэкенд

Отправка заказа сосредоточена в одной функции — `placeOrder()` в
`CartDrawer.vue`. Сейчас она вызывает `openLink(ссылка на чат)`. Для варианта
с ботом вместо этого она отправит `POST /api/orders` со списком `{id, quantity}`
и `Telegram.WebApp.initData`. Бэкенд (Kotlin) проверит подпись `initData`,
пересчитает сумму по своей базе и отправит сообщение менеджеру от имени бота.
Корзину, карточки и остальной интерфейс при этом менять не придётся.

## Telegram Mini App

Страница уже готова к работе как Mini App: SDK подключён в `index.html`,
`initTelegram()` в `main.js` раскрывает приложение на весь экран и красит
шапку, а ссылка на менеджера внутри Telegram открывается нативно
(`openTelegramLink`). В обычном браузере всё это просто не срабатывает.

Чтобы запустить:

1. Выложите собранный сайт (`npm run build`, папка `dist/`) на любой хостинг
   с **HTTPS** (GitHub Pages, Cloudflare Pages и т. п.). Telegram не открывает
   Mini App по `http://`.
2. Создайте бота в `@BotFather` (`/newbot`).
3. Привяжите приложение: `/newapp` (отдельное Mini App со своей ссылкой) или
   `/setmenuurl` (кнопка меню у бота). В обоих случаях укажите HTTPS-адрес
   сайта.
4. Выкладка в подпапку (GitHub Pages: `https://<логин>.github.io/<репозиторий>/`)
   уже поддерживается и отдельной настройки не требует: пути к скриптам,
   `products.json` и фото относительные (`base: "./"` в `vite.config.js`).
   Условие: фото в `products.json` указаны без `/` в начале, это проверяет
   `npm test`.

Менеджеру (`@kompot_lego`) заказы приходят как обычные личные сообщения от
покупателей, никаких настроек бота для этого не требуется.
