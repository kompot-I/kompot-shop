# Как заполнять каталог

Весь каталог — один файл: `public/products.json`. Сайт читает его при каждой
загрузке, поэтому для нового товара достаточно добавить запись в этот файл и
положить фото в `public/images/`. Код менять не нужно.

## 1. Шаблон товара

Копируйте блок целиком и меняйте значения:

```json
{
  "id": "sw-009",
  "name": "Джедай-рыцарь",
  "category": "Star Wars",
  "description": "Полный комплект: световой меч и плащ. Без сколов.",
  "price": 1200,
  "currency": "RUB",
  "quantity": 1,
  "condition": "used",
  "image": "images/sw-009.jpg"
}
```

Файл устроен так: внутри `"products": [ ... ]` товары идут через запятую.
Порядок в файле = порядок на сайте при сортировке «По умолчанию», поэтому то,
что хотите показать первым, ставьте выше.

```json
{
  "products": [
    { ...товар 1... },
    { ...товар 2... }
  ]
}
```

## 2. Поля

| Поле | Что писать |
|---|---|
| `id` | Уникальный код: строчная латиница, цифры, дефис. Например `sw-009`, `hp-003`. |
| `name` | Название, коротко. В карточке занимает 1–2 строки. |
| `category` | Серия: `Star Wars`, `City`, `Ninjago`. Пишите всегда одинаково. |
| `description` | 1–2 предложения: комплект, дефекты. |
| `price` | Цена за **одну** штуку, целое число в рублях: `1200`. |
| `currency` | Всегда `"RUB"`. |
| `quantity` | Сколько штук в наличии, целое число от `0`. |
| `condition` | Ровно одно из: `new`, `like_new`, `used`. |
| `image` | `"images/имя-файла.jpg"`, полная ссылка `"https://..."` или `""` (тогда заглушка). |

Подробности, которые легко упустить:

- **`id`**: не повторяйте и не меняйте у существующих товаров. По нему корзина
  покупателя запоминает позицию. Не отдавайте старый `id` другой фигурке. Менеджер
  видит `id` в тексте заказа, так что префикс серии и номер (`sw-009`) помогают
  быстро найти фигурку.
- **`category`**: по ней работает поиск. `Star Wars` и `Звёздные войны` для сайта
  разные серии.
- **`description`**: в карточке видно только две строки (примерно 80–110
  символов), остальное обрезается, полного описания нигде нет. Самое важное
  пишите в начале.
- **`price`**: без кавычек, пробелов и знака `₽`. Правильно: `1200`.
  Неправильно: `"1 200 ₽"`.
- **`quantity`**: покупатель не сможет положить в корзину больше этого числа.
  При `0` на карточке появляется «Продано» и кнопка блокируется. Сайт **сам не
  уменьшает** остаток после продажи: после сделки поправьте число вручную.
- **`condition`**: другие слова не сработают, от значения зависят фильтры и цвет
  метки: `new` (новый), `like_new` (как новый), `used` (б/у).
- Одна и та же фигурка в одинаковом состоянии и по одной цене: **одна запись**
  с `quantity` больше единицы. Другое состояние или цена: **отдельная запись** с
  другим `id`.
- Поле `buyLink` больше не нужно, его можно не писать.

## 3. Фотографии

1. Положите файл в `public/images/`. Удобно называть его так же, как `id`:
   `public/images/sw-009.jpg`.
2. В товаре напишите путь **без `/` в начале**: `"image": "images/sw-009.jpg"`.

Что важно:

- **Имя файла**: строчные латинские буквы, цифры, дефис; расширение тоже
  строчное (`.jpg`, не `.JPG`). На macOS регистр букв не важен, а на хостинге
  важен: `IMG_8400.PNG` у вас откроется, а после публикации нет. Эту ошибку
  ловит `npm test`.
- **Формат**: JPG или WebP. PNG берите, только если нужен прозрачный фон.
- **Размер**: длинная сторона 800–1200 px, вес примерно до 300 КБ. Снимок с
  телефона на 3–5 МБ каталог будет грузить очень долго. Сжать можно в
  «Просмотре» на macOS (Инструменты → Настроить размер, Файл → Экспортировать)
  или на squoosh.app.
- **Пропорции любые**: фото целиком вписывается в квадрат по центру без
  обрезки, вертикальный кадр тоже подойдёт, по бокам останется тёмный фон.
- **Фон на фото**: карточки тёмные, поэтому снимок на белом фоне выглядит как
  белый прямоугольник. Лучше однотонный нейтральный фон либо вырезанный фон
  (PNG/WebP с прозрачностью).

## 4. Типичные ошибки в JSON

- Между товарами нужна запятая (`},`), а после **последнего** товара запятой нет.
- Кавычки только прямые двойные `"`. Внутри текста используйте «ёлочки».
- Числа пишутся без кавычек: `"price": 1200`.
- Комментарии в JSON запрещены.

Если после правки сайт показывает «Каталог не загрузился», в файле ошибка
синтаксиса, IDEA подчёркивает её красным.

## 5. Проверка

```bash
npm test        # проверит products.json и скажет, какой товар и какое поле не так
npm run dev     # посмотреть результат глазами
```

`npm test` проверяет: корректность JSON, обязательные поля, уникальность `id`,
допустимые `condition`, формат `price` и `quantity`, и что файл фото существует
(с учётом регистра букв).

## 6. Когда товар продан

- Поставьте `"quantity": 0`: карточка останется с отметкой «Продано», витрина
  выглядит «живой».
- Или удалите запись (и фото): каталог остаётся компактным.

Корзины покупателей подстраиваются сами: исчезнувшие товары убираются, а
количество подрезается по остатку. Чтобы правки появились на сайте, нужны
коммит и публикация (когда сайт будет выложен).
